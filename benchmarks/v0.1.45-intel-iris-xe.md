# Fern v0.1.45 benchmark on Intel Iris Xe

Measured November 20, 2026 in the Windows Electron app on Intel Iris Xe Graphics, with 32 GiB of RAM, Windows 11 Pro build 22621 and Intel driver 32.0.101.7084. The published Windows v0.1.45 package was used for the main results. [Release](https://github.com/xgirls-dev/fern/releases/tag/v0.1.45) · [Timing data and workload settings](v0.1.45-intel-iris-xe.json)

## Image, video, and speech

Times are seconds from clicking Generate until the app decoded the image, showed the audio take, or loaded the video preview. Each first run starts in a new Electron session with installed weights and existing disk caches. The immediate repeat uses the same app session and inputs, with fixed seeds for image and video. Each pair has one sample per condition.

A separate local test of the Klein 4B rank-8 loader patch took **85.6 seconds** on the first run and **41.8 seconds** on repeat at 512 × 512 and four steps. This row uses a modified v0.1.45 payload. [Patch verification in issue #16](https://github.com/xgirls-dev/fern/issues/16#issuecomment-7031510132)

- Fern explicitly logged reuse of the loaded model for SANA-Sprint and Qwen speech. Speech synthesis plus waveform decoding took 26.2 and 22.3 seconds for takes lasting 4.54 and 3.82 seconds.
- Kromoss reused prompt conditioning. Its runtime logged 5.67 seconds for conditioning on the first run and 0.00 seconds on the cache hit. The repeat still ran all eight denoising steps.
- Wan loaded the model in a separate inference process for each clip. The timings include model loading, frame generation, decoding, and WebM writing.
- Z-Image completed both runs and displayed both results in the gallery.

## Multi-turn Gemma 4 E4B

Gemma 4 E4B used Q4_0 GGUF weights and the Q8_0 vision projector with an 8K context window. Text used OpenVINO GPU and vision used Vulkan GPU. Each three-turn conversation ran twice, in both Instant and Reasoning modes. Gemma answered all 24 turns correctly. Vision attached the image on turn one and recalled it on later turns without another attachment.

| Opening reply | First conversation | Repeated conversation |
| --- | ---: | ---: |
| Instant text | 72.6 s | 1.9 s |
| Instant vision | 10.8 s | 0.9 s |
| Reasoning vision | 19.8 s | 16.8 s |

The first Instant text and vision replies include startup for their respective backends. The repeated Instant vision opening evaluated **6 of 111 prompt tokens**, as recorded by llama.cpp. Its two follow-ups finished in about **1.4 seconds** each. The short text recall prompts produced zero reasoning characters even with Reasoning selected. The vision reasoning opening produced a reasoning trace on both runs.

In Chat-to-image with SANA-Sprint, the first image appeared in **86.9 seconds**. Two later requests for the same poster took **12.3 and 14.7 seconds** to first pixels. Chat generates a fresh seed for each image and conversation context grows between turns. Follow-up checks retained the project code and earlier image at 4K, 8K, and 16K context.

## Rerunning the workloads

Use the model revisions, prompts, settings, and input fingerprints in the [timing data](v0.1.45-intel-iris-xe.json). Open a new Fern process for each workload, run it once, and submit the same parameters again in the same session as soon as the first result is visible. For the Gemma replay, start a new thread with the same settings and repeat all three turns without restarting Fern.

The input fingerprints identify the ordered reference images used in this run. Reference pixels are not included, so substituting images produces a comparable workload with different inputs. The reported generation timers are specific to each runtime. The first-run and repeat columns use the app-level timing described above.
