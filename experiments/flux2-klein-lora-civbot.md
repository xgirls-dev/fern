# FLUX.2 Klein 4B LoRA: Civbot investigation

**Update, 2026-11-11:** The dedicated [LoRA-ready INT4 model](https://huggingface.co/xgirls/FLUX.2-klein-4B-OpenVINO-INT4-LoRA) and Fern's text-to-image LoRA controls have since been tested together in the Electron app on Intel GPU. The historical notes below describe the state of each earlier experiment; image editing and 9B LoRAs remain unverified.

The complete Civbot LoRA produced the expected blue robot on Intel GPU with a fresh INT4 export of `black-forest-labs/FLUX.2-klein-4B`. The image is `outputs/lora-civbot/civbot-klein4b-lora-1.9-converted.png`; the same prompt and seed without an adapter produced `civbot-klein4b-baseline-512.png`.

The test used the Civitai sample prompt `(Blue CivBot, Gigachad, Sigma male), Sitting on a toilet bowl in an abandoned restroom, graffiti on walls that says : "FREE HUGS", Pixar style`, seed 726532356, 12 steps, 512 by 512 pixels, guidance 1.0, and adapter strength 1.9. GenAI rejects a negative prompt at guidance 1.0, so the sample's negative prompt was omitted. OpenVINO GenAI and OpenVINO were 2026.4.1. The successful export used the repo environment's Optimum Intel `1.27.0.dev0+7234214`, Diffusers 0.40.0, Transformers 5.0.0, and NNCF 3.4.0. An earlier version of these notes incorrectly attributed it to Optimum Intel 2.2 and Transformers 5.2: a malformed PowerShell `PYTHONPATH` left those overlays unused.

The original AI-Toolkit safetensors used BFL `diffusion_model.double_blocks` and `single_blocks` keys. Passing it directly to GenAI silently produced the exact baseline image. Diffusers' `_convert_non_diffusers_flux2_lora_to_diffusers` converted it to 200 Diffusers-format tensors. The full converted adapter initially failed in GenAI's LoRA graph rewrite on attention projections fed directly by `VariadicSplit` outputs. Inserting a same-type `Convert` between each of the ten split outputs and the subsequent MatMul allowed the full adapter to run and produce the robot.

The export also needed two compatibility bridges for GenAI: expose the text encoder's concatenated 7680-wide prompt embedding as three 2560-wide outputs named `hidden_states.9`, `.18`, and `.27`; and accept rank-three image/text IDs then squeeze the batch dimension before the transformer's rank-two inputs. VAE batch norm stats from `vae_bn_stats.npz` were added to the temporary decoder config. Prototype scripts and generated model copies are in `tmp/`.

Applying the same bridges to a copy of Fern's installed `xgirls/FLUX.2-klein-4B-ov-int4` produced a normal baseline (`civbot-fern-model-baseline.png`) but corrupted output with the full adapter (`civbot-fern-model-full-lora.png`). Thus the fresh export is a working proof, while compatibility with the existing installed quant is unresolved. No Fern UI or runtime integration has been completed. Investigate the old quant's weight layout/LoRA interaction before offering it in the app; do not silently accept unmatched adapter tensors.

## Reproducing the working combination

Fern's existing encoder and VAE work with the fresh transformer: the hybrid run produced `outputs/lora-civbot/civbot-hybrid-lora.png`. `experiments/prepare_flux2_klein_lora.py` prepares this combination in a new directory, converts BFL-format adapters, and validates that every adapter target has both matrices and matches a transformer MatMul. Its output produced `civbot-repro-lora.png` with all 100 Civbot targets accounted for.

The fresh transformer came from an export of the public `black-forest-labs/FLUX.2-klein-4B` Diffusers checkpoint using `optimum-cli export openvino --library diffusers --task text-to-image --weight-format int4 --group-size 128 --group-size-fallback adjust`. Point `--transformer` at the export's transformer directory, `--fern-model` at the installed 4B directory, `--lora` at the safetensors file, and `--output` at a new directory. The tool writes `adapter.safetensors` alongside the prepared GenAI model. Register that adapter in `Text2ImagePipeline`'s constructor and use device `GPU`.

This prepares a separate experimental copy; it does not install the new transformer or add LoRA controls to Fern. The original quant remains incompatible with the full adapter in the tested GenAI path.

## Two adapters: Civbot and PXART4

On Intel GPU, registered the complete Civbot adapter and the existing `adirik/pixel-art-lora-flux.2-klein-4B` adapter in one GenAI pipeline. Each converted to 100 complete targets validated against the transformer. A same-pipeline, same-seed comparison used `PXART4. (Blue CivBot, Gigachad, Sigma male), Sitting on a toilet bowl in an abandoned restroom, graffiti on walls that says : "FREE HUGS"`, 512x512, seed 726532356, 12 steps and guidance 1.0. Civbot strength was 1.9; pixel adapter strength was 1.0. The Civbot-only result is `outputs/lora-civbot/civbot-only-pxart4.png`, and the combined result is `civbot-and-pixelart-pxart4.png`. Both showed the blue robot; the combined result changed the composition, but neither image was visibly pixel art. Timings after pipeline initialization were 145.7 seconds and 123.2 seconds respectively.

A second combined run used pixel effective scale `64/sqrt(128)` (about 5.657), derived from the model card's alpha 64, rank 128 and rsLoRA setting, with other settings unchanged. `civbot-pixelart-rslora-scale.png` changed further but was still a smooth illustration, not pixel art. These results show that GenAI accepts both adapters together and that adding the second changes the output; they do not establish that the pixel-art LoRA produces its intended style on distilled Klein. Its model card labels it as trained for Klein 4B Base and uses Base in its code example, while its training table names Klein 4B, so its intended checkpoint is ambiguous. No Fern UI integration was tested.

## Two-adapter demonstration: Civbot and fal claymation

The `claymation/pytorch_lora_weights.safetensors` adapter from [rehan-fal/klein-style-fleet](https://huggingface.co/rehan-fal/klein-style-fleet) has SHA-256 `32bfa0d7450d725e7a007ead6a05bd2759ee0cad8fa082a1b1bb04d344b5c988` and all 100 complete targets matched the prepared transformer. The author recommends the distilled Klein 4B at 4 steps and trigger `claymtn style`.

Both images used the same OpenVINO GenAI Intel GPU pipeline, prompt `claymtn style, Blue CivBot, Gigachad, Sigma male, standing in a forest`, seed 726532356, 512x512, guidance 1.0 and 4 steps. The Civbot-only control used strength 1.9 (`outputs/lora-civbot/civbot-only-clay-prompt.png`, 56.4 seconds); adding claymation at 1.0 produced `outputs/lora-civbot/civbot-and-clay.png` (49.8 seconds). The control is a comic illustration and the combined image is visibly a blue clay figure, preserving the Civbot identity. Both adapters were registered in the same pipeline, with the control generated by passing the Civbot-only configuration. This is a backend proof using the compatible replacement transformer, not a Fern UI test.
